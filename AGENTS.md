# Nested

Windows-first desktop application for interior designers. Preserve the React / Three.js editor; work incrementally. The untouched ZIP/extraction is outside this checkout. Baseline commit: cc9ca253eaa6546b185c0a3f4ae2f3a52bd53193.

- Keep Node and filesystem access in Electron main; expose only narrow, validated preload operations. No provider credentials or server API code in the distributed application.
- Project state uses `shared/project.mjs`. Never treat the shopping-list export as a reopenable project. Validate before replacing live state; preserve backups and cancelled operations.
- Catalog entries and procedural/AI models are conceptual until provenance, dimensions, exact variant, material fidelity and usage rights are verified. Do not invent missing product facts or recolor verified retail finishes.
- Improve interactive rendering first. Blender is optional. Inspect actual images and report measurements; do not claim unmeasured performance or retail accuracy.
- Nested is desktop-only (decision 2026-09-28). The prototype's Vercel server API, AI model generation, retailer page reading, online address lookup, browser storage and browser preview were removed; they remain in Git history before that date. Do not reintroduce a web service or network calls without an explicit authorized design. `npm test` / `npm run test:offline` run all Node tests (all offline).
- Desktop commands and validation outcomes are recorded in `docs/progress.md`. Keep this record current, distinguishing built, launched, visually inspected, and installer-tested.
- Verified desktop commands: `npm run desktop:start`, `npm run test:desktop` (real Electron with dialog selections stubbed), and `npm run desktop:dist` (Windows ARM64 + x64 NSIS). After packaging, `node scripts/packaged-check.mjs [exe]` launches a packaged build and checks it. `npm run test:offline` now includes project persistence tests. Keep the Electron main module's app-ready work in a callback: top-level awaiting `app.whenReady()` prevents ESM main loading from completing.
- Imported models (`shared/assets.mjs`, `src/three/assetLoader.js`) load through standard GLTFLoader, are stored by SHA-256 in the private `userData/assets` library and referenced by checksum from project format v2. Never route them through the tintable converter, recolour them, or infer units; unit/orientation corrections are explicit designer choices on the asset record.
- Rendering review: `VITE_NESTED_DEBUG=1 npx vite build` then `node scripts/scene-debug.mjs <name> "<js>"` captures real Electron canvas images to `artifacts/`. Rebuild normally afterwards (`npm run build` or `npm run test:desktop`); production builds must not expose `window.__nestedEngine`. Report frame timings with machine, canvas size and sample count.
- Interface target: `references/interface-target/` (approved 2026-09-29). Match its palette tokens, type and layout; the room itself must stay real 3D that feels like standing inside it (opens at eye level; walls cut away only when the camera is outside).
- Use `docs/product-brief.md`, `docs/audit.md` and `references/README.md` for continuity. No automatic cloud uploads or model-generation requests in desktop builds.
- Room studio shell (2026-09-29): tool rail (Room, Pieces, Finishes, Light, Views) | room | inspector, view strip below, presentation mode (P / Esc). Camera, lighting and saved views are project format v3 (`studio`, `views`; v1/v2 files migrate on open). Lighting sliders update the live scene in place (`applyStudio` in `RoomCanvas.jsx`); saved views and previews go through `src/three/viewBridge.js`. The prototype's demonstration room and palette were not used.
- Photographic materials: `src/three/photoMaterials.js` + `src/data/materialSources.js` + `public/materials/polyhaven/` (CC0, bundled, offline). Only catalog entries with `materialSet: 'pilot'` (the sofa and the round coffee table) use them; every other piece keeps its old builder. They are concept finishes, never retailer finishes. Base colour maps sRGB, normal/roughness linear, scale set by UVs in metres over the published tile size. Do not extend to other pieces until the pilot is accepted. `test/materials.test.mjs` verifies the files.
- Comparison workflow: `VITE_NESTED_DEBUG=1 npx vite build` then `node scripts/material-compare.mjs <label>` (`NESTED_LEGACY=1` renders the old pieces under current lighting). Rebuild normally afterwards.

- Brief (2026-09-29): written in-app; no upload. Draft and Brief live in project format v5. The AI Brief chat (multi-turn, `BriefChat.jsx`) is the one authorized network call: Nested-hosted service via `NESTED_AI_URL`, Brief text only, allowlisted proposals the designer applies (`shared/briefAi.mjs`). Keep provider keys out of the app; `server/` is not packaged. Tests: `npm run test:brief`.
